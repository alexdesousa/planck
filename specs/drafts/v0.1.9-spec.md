# Planck v0.1.9 — Spec

## Overview

Seven areas: config modal fixes, hot-reload fix, model parameter controls, restart button, Forge-inspired error improvements, compactor improvement, and a version bump script.

---

## 1. Config Modal Fixes

### 1a. Dropdown selection not committed

**Bug**: provider and model dropdowns visually show a selected value but the selection is not actually committed until the user opens and re-selects from the dropdown. This results in saving a config entry with an empty `provider` or `id`.

**Fix**:
- Audit the LiveView event flow for the provider and model pickers — ensure the selected value is bound to the socket assign on `phx-change`, not only on explicit dropdown interaction
- Add validation before saving: reject if `provider` key or model `id` is blank/empty string
- Show an inline error message instead of saving silently

### 1b. Prevent empty named providers or models

**Fix**:
- `configure_provider/1` — validate `id` is non-empty before writing to config
- `configure_model/1` — validate `id` and `provider` are non-empty
- Return `{:error, :empty_id}` / `{:error, :empty_provider}` on violation
- SetupModal: surface validation errors inline next to the offending field

## 2. Config Hot-Reload Fix

**Symptom**: manually editing `config.json` requires a Planck restart for changes to take effect. The Watcher has a 300ms debounce which should be fast enough.

**Likely causes to investigate**:
- `JsonBinding` uses `:persistent_term` — `ResourceStore.reload/0` calls `Config.JsonBinding.invalidate()` but Skogsra's cache may not be fully flushed for all keys
- The file system backend (inotify on Linux, FSEvents on macOS) may not emit events for all editor save patterns (e.g. write-to-temp + rename, which some editors use)
- The Watcher only watches configured skill/team dirs — verify `config.json` parent dir is also watched

**Fix**:
- Add `config.json` and `.planck/` root dir to the Watcher's watched paths
- Add a `Logger.info` on reload with a list of changed files for debugging
- Verify `Config.JsonBinding.invalidate/0` and `Config.EnvBinding.invalidate/0` fully clear the persistent_term cache for all bound keys
- If editor rename-on-save is the issue, ensure the Watcher subscribes to `:created` events in addition to `:modified`

## 3. Model Parameter Controls

**Current state**: extra model parameters (temperature, top_p, etc.) are entered as a raw JSON object. This is flexible but unfriendly.

**New design**: common parameters get dedicated controls with defaults, ranges, and tooltip explanations. The raw JSON field remains for anything not covered.

### Parameters

| Parameter | Type | Default | Range | Description |
|---|---|---|---|---|
| `context_size` | integer | model-dependent | 512 – 131072 | Maximum context window in tokens. Higher values use more VRAM. |
| `temperature` | float | 1.0 | 0.0 – 2.0 | Randomness of output. Lower = more deterministic, higher = more creative. |
| `top_p` | float | 1.0 | 0.0 – 1.0 | Nucleus sampling threshold. Limits token selection to the top P probability mass. |
| `min_p` | float | 0.0 | 0.0 – 1.0 | Minimum probability threshold relative to the top token. Filters low-quality tokens. |
| `top_k` | integer | 0 | 0 – 200 | Limits token selection to the top K candidates. 0 = disabled. |

### UI

- Each parameter: label + numeric input + `?` icon
- Clicking `?` shows a tooltip with the description from the table above
- Inputs show the default value as placeholder when empty (empty = omit from config, model default applies)
- Raw JSON `params` field remains below for advanced overrides — if a key appears in both the controls and raw JSON, the raw JSON wins
- On save: merge control values into the `params` map, omit keys left at default/empty

### Implementation

- `planck_ai`: `Planck.AI.Model` gains typed fields for common params; they are passed to `req_llm` context options
- `planck_cli`: SetupModal step 2 gains the parameter controls section
- `planck_headless`: `configure_model/1` accepts the new fields

## 4. Restart Button

**Goal**: a UI button that restarts the main application supervisor without requiring a process kill or systemd restart. Useful after config changes or when the agent gets into a bad state.

### Behaviour

- Located in the status bar or settings area
- Clicking shows a confirmation dialog ("Restart Planck? Active sessions will be terminated.")
- On confirm: calls a `Planck.Headless.restart/0` function that stops and restarts the application supervisor
- The LiveView connection drops and reconnects automatically (Phoenix handles this)
- All active sessions are terminated; the user lands on the empty session state

### Implementation

```elixir
# planck_headless
def restart do
  Task.start(fn ->
    Process.sleep(100)  # let the HTTP response return first
    Application.stop(:planck_headless)
    Application.start(:planck_headless)
  end)
  :ok
end
```

- `planck_cli`: new `POST /api/restart` endpoint (authenticated if API key is set)
- SetupModal or status bar: restart button with confirmation
- The 100ms delay ensures the HTTP response reaches the client before the supervisor stops

## 5. Forge-Inspired Error Improvements

Source: [Forge](https://github.com/antoinezambelli/forge) + [author's HN comments](https://news.ycombinator.com/item?id=48192383).

### 5a. Retry nudges — biggest win

The author reports retry nudges are the single largest reliability improvement — without them, error recovery scored 0% across all tested models. The key insight: **domain-agnostic structural nudges** ("you returned text, I need a tool call") outperform detailed error traces because the model's training handles the context-specific fix once it understands what went wrong structurally.

**Current Planck behaviour**: tool execution errors are appended as a `tool_result` with the raw error. The model sees the error but gets no guidance on what it did wrong at a structural level.

**Proposed**: `Planck.Agent` detects specific error categories and injects a structured nudge alongside the error:

| Error category | Nudge |
|---|---|
| Model returned text instead of a tool call when tools are required | "Your response was plain text. Please call one of the available tools." |
| Tool call with malformed/missing arguments | "The tool call arguments were invalid. Please retry with correct arguments matching the schema." |
| Unknown tool name | "The tool `{name}` does not exist. Available tools: {list}." |

Nudges are injected as a system-role turn (not user-role) so they don't appear as user speech. Opt-out via `"nudges": false` in TEAM.json for models that handle errors well natively.

### 5b. Rescue parsing — 5–15% of small-model calls

Local models emit tool calls in non-standard formats that Planck's current parser rejects. Forge handles three formats beyond OpenAI JSON:

- **JSON in code fence**: ` ```json\n{"name": "...", "arguments": {...}}\n``` `
- **Mistral bracket syntax**: `[TOOL_CALLS]name{"arg": "val"}`
- **Qwen XML**: `<tool_call>{"name": "...", "arguments": {...}}</tool_call>`

**Proposed**: before failing a tool call parse, try each rescue parser in order. If one succeeds, proceed with a warning log. Lives in `planck_ai`'s stream event parser.

### 5c. `ToolError` distinction

Currently Planck surfaces all tool failures the same way. The author highlights the value of distinguishing:
- `{:error, :not_found}` — tool ran successfully but found no result (e.g. empty search)
- `{:error, :failed, reason}` — tool crashed or returned an actual error

**Proposed**: `Planck.Agent.Tool` result type gains a `:not_found` variant. The nudge system (5a) treats these differently — a not-found result gets "try a different query" rather than "fix your arguments".

### What does NOT apply

- **Tiered compactor**: dropped from this release — the compactor improvement in section 7 is the right fix.
- **Backend prompt-mode vs native function calling**: the author found a 76-point accuracy swing (7% → 83%) on the same model weights purely from switching inference backends. This is a documentation/guide issue for Planck, not a code change — worth noting in the model configuration guide.
- **GPU fallback detection**: not relevant for Planck.

## 6. Compactor — Token-Aware Keep-Recent

**Current behaviour**: the compactor always keeps the last 10 messages verbatim and summarises everything older. If those 10 messages are very long (e.g. a turn with large tool results), they may already exceed most of the context window, causing compaction to trigger on nearly every turn with little effect.

**New behaviour**: instead of a fixed count, keep messages from the tail of the history as long as their cumulative token estimate stays within `@keep_ratio` (default 10%) of the model's `context_window`. Work backwards from the most recent message, accumulating token counts until the budget is exceeded, then stop.

```
keep_budget = model.context_window * @keep_ratio   # e.g. 128k * 0.10 = 12,800 tokens

kept = []
for msg <- Enum.reverse(messages) do
  cost = Message.estimate_tokens([msg])
  if accumulated + cost <= keep_budget do
    kept = [msg | kept]
    accumulated = accumulated + cost
  else
    break
  end
end
```

**Edge case**: if the single most recent message already exceeds `keep_budget`, keep it anyway (minimum 1 message kept) so the agent always has at least its last action in context.

**Configuration**: `@keep_ratio` hardcoded at `0.10`. Can be exposed as a TEAM.json option (`"compactor_keep_ratio": 0.15`) in a future release if needed.

**Impact**: on long tool-heavy turns, far fewer messages are kept verbatim, giving the summariser more to work with and reducing re-compaction frequency.

**Files**: `planck_agent/lib/planck/agent/hooks/compactor.ex` — replace `@default_keep_recent 10` and the `Enum.split(messages, -@default_keep_recent)` call with the token-budget loop.

## 7. Version Bump Script

**Goal**: replace the manual 12-file version bump with a single command.

```sh
./bump 0.1.9
```

### Files updated

Per the release checklist in `specs/releases-and-distribution.md`:

| File | Update |
|---|---|
| `VERSION` | Replace version string |
| `planck_ai/mix.exs` | `@version` |
| `planck_agent/mix.exs` | `@version` |
| `planck_headless/mix.exs` | `@version` |
| `planck_cli/mix.exs` | `@version` |
| `planck_docker/sidecar/mix.exs` | `version:` |
| `planck_docker/compose.yml` | image tag (both entries) |
| `skills/planck_setup/SKILL.md` | `planck_version:` |
| `docs/install.sh` | `VERSION=` |
| `docs/install.ps1` | `$Version =` |
| `docs/install_docker.sh` | `VERSION=` |
| `docs/install_docker.ps1` | `$Version =` |

### CHANGELOG stubs

For each package CHANGELOG, prepend:

```markdown
## vX.Y.Z

- TODO

```

### Script behaviour

- Reads current version from `VERSION`
- Validates new version is semver and greater than current
- Performs all substitutions
- Prepends CHANGELOG stubs
- Prints a summary of changed files
- Does NOT commit or tag — that remains a manual step after review

### Implementation

A plain shell script (`./bump`) — no dependencies beyond `sed` and `grep`.

```sh
#!/usr/bin/env bash
set -e
NEW=$1
OLD=$(cat VERSION)
# ... substitutions
echo "Bumped $OLD → $NEW. Run ./check before committing."
```
