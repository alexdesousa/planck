# Planck v0.3.1 — Spec

## Scope

RLCD-gated agentic judgment (`ask`/`ask_files`) plus a pre-tool-call
safety gate with human-in-the-loop approval:

1. **Hard rename `classify` → `ask`** — same schema, same RLCD-gated
   orchestrator auto-include, no alias (`planck_agent`). Breaking;
   reason for the minor bump.
2. **New `ask_files` core tool** — same gate as `ask`, explicit paths
   only, one RLCD call per file (cap 16 concurrent, 255 files),
   `{results, skipped, calls}` envelope. Reads via the *live* `read`
   tool (sidecar shadow wins when present), builtin fallback
   (`planck_agent` + `planck_headless` wiring; also fixes the
   worker-grant gap for both tools).
3. **Three new hook behaviours** — `ToolStart.proceed/3` (sync gate),
   `ToolEnd.transform/4` (sync result transformer, UI-capable),
   `TurnStart.notify/2` (async observer). Pipeline becomes
   validate → gate → execute → loop-nudge → transform → UI extraction.
   Result type gains `{:error, reason, %{ui:}}` (`planck_agent`).
4. **Approval loop** — `:await_approval` parks the call, approving
    runs the stored `execute_fn` with the exact parked args (one-shot;
    second resolve returns `:not_found`), denying completes a plain
    denial error (`planck_agent` + `planck_headless`).
5. **Bundled `BashGate`** — park-only gating over the upstream
    `BASH_QUESTIONS` block (model verdicts park, never deny;
    transport failures deny loudly), thresholds via env, no tagger /
    ETS / session-start hold by design (`planck_docker/sidecar`).
6. **CLI approval modal** — `ApprovalModal` LiveComponent fed by
    `:tool_blocked` + `list_all_pending_approvals/1`, auto-shown while
    parked calls exist (`planck_cli`).
7. **Docs** — `teams.md`, `hooks.md`, `tool-shadowing.md`, CHANGELOG.

In scope: everything above. Out of scope: `ToolEnd` enrichment of
`ask`/`ask_files` output (identity default holds), global confidence
thresholds (agent gates on raw probabilities), glob/dir expansion in
`ask_files` (agent narrows via `search_workspace` first).

## Objective

Give the orchestrator fast, calibrated RLCD judgment over single
states (`ask`) and file batches (`ask_files` — e.g. "is this file
related to <bug>?", act where `noul > Y`), while every dangerous tool
call passes a sidecar gate that can allow, deny, or park for human
approval in a modal. Upstream reference for the decision shapes:
`disler/ten-levels-of-jev` (L6 bash-gate, L8 ask-file, L9 ask-files).

## Use Cases

- An orchestrator triaging a bug calls `ask_files` with 40 candidate
  paths and one boolean question; it re-`read`s only the 3 files with
  `noul > 0.7` and fixes the bug without ever loading the other 37.
- An agent about to run `rm -rf _build` gets `:await_approval`; the
  user sees the exact command + the gate's reason in a modal, approves,
  and the command runs once — a second, different command re-gates.
- An agent about to run a destructive wipe gets `{:deny, reason}`;
  the model sees the reason + "do not work around this" and stops.
- A session started while the sidecar is still booting waits instead
  of running `bash` ungated.

Scope/Objective/cross-cutting Use Cases/non-goals, then follow the
links below for the step you're implementing. Steps are written with

## Explicitly not touched

- **`boolean` question type is NOT renamed to `noul`.** Upstream calls
  it `noul`; Planck keeps `boolean` to avoid a second breaking change.
  Equivalence is documented in the prompt section.
- **No tool-side confidence thresholds.** Tools return raw
  probabilities; the agent picks gate cutoffs per call. The only
  numeric thresholds in the system are the `BashGate` safety constants
  (env-configured, Step 5).
- **No glob/dir/recursive expansion in `ask_files`.** Explicit paths
  only; the agent expands via `search_workspace`.
- **`ToolEnd` enrichment of `ask`/`ask_files` output.** Deferred;
  identity default holds.
- **`TurnStart` prompt injection.** `Prompt` remains the sole sync
  injector; `TurnStart` is observer-only (memory warmup, metrics).
- **Builtin `bash`.** Byte-identical; the gate lives entirely in the
  hook layer.

## Behavioral changes worth flagging

- **`classify` disappears.** Sessions/teams referencing it break loudly
  (unknown tool) — intended, no shim.
- **Sessions declaring `tool_start_hook` wait for sidecar
  `:connected`** (bounded wait, then fail-open + loud log) instead of
  running the first turns ungated.
- **Tool results can now carry UI on errors** (`{:error, reason,
  %{ui:}}`) — additive; existing 2-tuple errors flow unchanged.
