# Planck v0.1.7 — Release Spec

## Overview

Two new lean behaviours in `planck_agent` and a skill system overhaul.

**`Planck.Agent.PromptHook`** (shipped) — sidecar hook called before every LLM
turn. The sidecar implements it to inject per-session memory into the system
prompt (prepend and/or append). Planck core has no knowledge of memory storage
or retrieval.

**`Planck.Agent.TurnEndReflector`** — sidecar hook called after every LLM turn
ends. The sidecar implements it as a `SkillReflector`: detects repeatable
workflows (threshold: tool call count), writes skills, and injects a synthetic
tool result into the parent agent's history so the LLM passively sees what was
captured on the next turn.

**Skill system overhaul** — the skill index gains frontmatter-driven pinning
(`always_present`) and a per-project SQLite usage database (replaces
`use_count`/`last_used` in frontmatter). The `write_skill` built-in tool and
a `planck_setup` bundled skill replace the `## Planck guides` section in the
default system prompt. The self-improvement loop is entirely in the sidecar via
`TurnEndReflector` — no self-improvement guidance is injected into the core
system prompt.

Dynamic workers (spawned via `spawn_agent`) are unaffected — they remain
purely task-scoped and ephemeral.

## Phase 1 — `PromptHook` behaviour (`planck_agent`) ✓ SHIPPED

`Planck.Agent.PromptHook` is the sidecar contract for per-turn system prompt
injection. Shipped in v0.1.7. See `specs/sidecar.md` for the full ETS-backed
implementation pattern.

```elixir
@callback prepend(session_id :: String.t() | nil) :: String.t() | nil
@callback append(session_id :: String.t() | nil) :: String.t() | nil
@callback hook_timeout() :: pos_integer()
```

`AgentSpec.prompt_hook` — `String.t() | nil` — module name declared in
TEAM.json. `PromptHook.build/2` converts it to `system_prompt_prepend_fn` and
`system_prompt_append_fn` closures passed to the agent at start time.

The sidecar implements `PromptHook` as a memory module: an ETS-backed GenServer
keyed by `session_id`, refreshed on `:compacted` PubSub events, backed by
Typesense for persistence. Planck core never touches memory storage.

## Phase 2 — `TurnEndReflector` behaviour (`planck_agent`)

### Behaviour

```elixir
defmodule Planck.Agent.TurnEndReflector do
  @callback reflect(
              agent_id :: String.t(),
              turn_messages :: [Planck.Agent.Message.t()],
              tool_call_count :: non_neg_integer()
            ) :: :ok

  @callback reflect_threshold() :: pos_integer()
end
```

`use Planck.Agent.TurnEndReflector` injects defaults:
- `reflect/3` — no-op, returns `:ok`
- `reflect_threshold/0` — returns `5`

### `build/2`

```elixir
TurnEndReflector.build("MySidecar.Reflectors.Skill",
  sidecar_node: node,
  agent_id: agent_id
)
# → [on_turn_end: fn]
```

Returns `[on_turn_end: fn]` — a closure with signature
`(turn_messages, tool_call_count) -> :ok`. The closure:

1. Checks `tool_call_count >= module.reflect_threshold()` — returns `:ok`
   immediately if not met (common case, zero allocation).
2. Dispatches `module.reflect/3` via `:rpc.call/5` to the sidecar node.
3. On `:badrpc`, logs a warning and returns `:ok` — never raises.

Returns `[]` when `name` is `nil`.

### Agent wiring

New field in `%Planck.Agent{}`:

```elixir
on_turn_end: (([Message.t()], non_neg_integer()) -> :ok) | nil
```

After `do_stream_done/1` broadcasts `:turn_end`, if `on_turn_end` is set, fire
it in a background `Task` (non-blocking, non-linked — agent stays idle
immediately):

```elixir
if state.on_turn_end do
  turn_msgs = TurnContext.current_turn_messages(state.messages)
  tool_count = ToolRunner.call_count(state.turn_state)
  Task.Supervisor.start_child(Planck.Agent.TaskSupervisor, fn ->
    state.on_turn_end.(turn_msgs, tool_count)
  end)
end
```

### `AgentSpec` changes

```elixir
turn_end_reflector: String.t() | nil  # e.g. "MySidecar.Reflectors.Skill"
```

Parsed from TEAM.json as `"turn_end_reflector"`. Resolved in headless via
`TurnEndReflector.build/2`.

### Sidecar — `SkillReflector`

The sidecar implements `TurnEndReflector` as a `SkillReflector`. When threshold
is met, it:

1. Inspects `turn_messages` to extract tool calls and outcomes.
2. Queries the skill usage SQLite DB (see Phase 3) to check existing skills.
3. Decides: new skill, update existing, or skip.
4. If writing: calls `write_skill` logic directly (no spawned agent), writes the
   `SKILL.md` file to the project skills directory.
5. Injects a synthetic tool result into the parent agent's message history via
   `Agent.inject_tool_result/3` (see below) so the LLM passively sees what was
   captured on the next turn.

The synthetic tool result uses a tool name (e.g. `"skill_reflector"`) that is
**not** in the agent's callable tool list — it appears only in history. The LLM
sees evidence of what happened without being able to re-invoke it.

### `Agent.inject_tool_result/3`

New public API:

```elixir
@spec inject_tool_result(agent(), String.t(), String.t()) :: :ok
```

Appends a synthetic assistant tool-use message paired with a tool-result message
to the agent's history and persists both, without triggering a new turn. The
tool name need not be in the agent's `tools` map.

## Phase 3 — Skill system overhaul (`planck_agent`, `planck_headless`)

### Frontmatter

Skills gain two optional frontmatter keys (dropping `use_count`/`last_used` —
usage is tracked in SQLite, not in files):

```markdown
---
name: my-skill
description: Does something useful.
always_present: false
planck_version: null
---
```

- `always_present` (default `false`) — when `true`, the skill is always included
  in the system prompt index regardless of usage. Intended for user-curated
  skills. Agent-created skills always write `false`; users may flip it manually.
- `planck_version` — set by Planck on bundled skills; used by upgrade logic to
  detect stale content. `null` on user- and agent-created skills.

### Skill usage SQLite DB

Per-project file: `.planck/skills.db`

Schema:

```sql
CREATE TABLE skill_usage (
  agent_id    TEXT NOT NULL,
  skill_name  TEXT NOT NULL,
  use_count   INTEGER NOT NULL DEFAULT 0,
  last_used   TEXT,                        -- ISO 8601 datetime
  PRIMARY KEY (agent_id, skill_name)
);
```

`load_skill` upserts a row (`use_count + 1`, `last_used = now()`) on every call.

**Top-5 index per agent:**

```sql
SELECT skill_name FROM skill_usage
WHERE agent_id = ?
ORDER BY last_used DESC, use_count DESC
LIMIT 5;
```

**Dynamic orchestrators** — top-5 across all orchestrators in the team:

```sql
SELECT skill_name FROM skill_usage
WHERE agent_id IN (SELECT agent_id FROM skill_usage WHERE ...)
ORDER BY last_used DESC, use_count DESC
LIMIT 5;
```

(exact query TBD at implementation; filter by `team_id` prefix on `agent_id`.)

The DB file is created on first `load_skill` call if it does not exist.

### Skill index assembly

At session start the system prompt skill index is three parts:

1. **Pinned** — all skills with `always_present: true`, always included.
2. **Last used** — up to 5 skills from the SQLite top-5 query for this agent.
3. **Discovery line** — *"Call `list_skills` to discover more skills."*

Example:

```
## Skills

- **git-workflow**: Branching, commit, and PR conventions for this repo.

## Last used skills

- **elixir-dev**: Elixir/Mix project conventions, test patterns, and credo config.
- **planck-setup**: Guides for configuring Planck.

Call `list_skills` to discover more skills.
```

The index is frozen for the session. At compaction it is rebuilt from disk and
the SQLite DB — newly created skills become visible in the index for the rest of
the session.

### `write_skill` built-in tool

```
write_skill(name, description, content)
```

- `name`: kebab-case skill name (e.g. `"git-workflow"`)
- `description`: one-line description ≤ 500 chars
- `content`: markdown body (everything after the frontmatter block)

Scope is always project (`.planck/skills/<name>/SKILL.md`). No `scope` param —
agent-written skills are workspace-scoped only.

**Behaviour:**

Writes:

```markdown
---
name: <name>
description: <description>
always_present: false
planck_version: null
---

<content>
```

If a `SKILL.md` already exists: overwrites body and `description`, preserves all
other frontmatter keys (user-set `always_present: true` is safe across updates).

Creates the skill directory if it does not exist.

### Bundled `planck_setup` skill

The `## Planck guides` section is removed from `DefaultPrompt.orchestrator/0`
and replaced with:

```
Call load_skill("planck_setup") before answering questions about configuring Planck.
```

The guides content becomes `~/.planck/skills/planck_setup/SKILL.md`. Frontmatter:

```markdown
---
name: planck-setup
description: Guides for configuring Planck — providers, models, teams, skills, sidecars, and the HTTP API.
always_present: false
planck_version: 0.1.7
---
```

**Upgrade logic** (`planck_headless` application start):

1. File does not exist → create with bundled content and default frontmatter.
2. File exists, `planck_version` matches running version → no-op.
3. File exists, `planck_version` differs → rewrite body and update
   `planck_version`; preserve all other frontmatter keys.

## Phase 4 — Typesense session index (sidecar)

The Docker sidecar indexes turns into a dedicated `planck_sessions` Typesense
collection and provides a `session_search` tool that shadows the (not yet
implemented) core SQLite FTS path. The sidecar implementation is the primary
path for v0.1.7.

### Collection schema

```json
{
  "name": "planck_sessions",
  "fields": [
    {"name": "id",         "type": "string"},
    {"name": "session_id", "type": "string", "facet": true},
    {"name": "team_alias", "type": "string", "facet": true},
    {"name": "agent_name", "type": "string", "facet": true},
    {"name": "role",       "type": "string", "facet": true},
    {"name": "content",    "type": "string"},
    {"name": "timestamp",  "type": "int64"}
  ],
  "default_sorting_field": "timestamp"
}
```

`id` is `"#{session_id}:#{db_id}"` — globally unique and stable. Idempotent on
upsert.

### Ingestion — `Sidecar.SessionIndexer`

`planck_agent` broadcasts on `"planck:turns"` PubSub topic after every turn:

```elixir
Phoenix.PubSub.broadcast(Planck.Agent.PubSub, "planck:turns",
  {:turn, team_alias, agent_name, session_id, db_id, message})
```

`Sidecar.SessionIndexer` (new GenServer in the Docker sidecar) subscribes at
startup and upserts each turn to `planck_sessions`. Indexes `:user` and
`:assistant` text/thinking content. Skips tool call/result parts and short
acknowledgment messages (< 20 chars).

### `session_search` sidecar tool

Queries `planck_sessions` filtered by `team_alias` + `agent_name`. Returns text
excerpts — same format as any future core SQLite implementation.

## Non-goals for v0.1.7

- **Core `session_search`**: the SQLite FTS built-in is not implemented. The
  sidecar Typesense tool is the only `session_search` path in v0.1.7.
- **SOUL.md**: `system_prompt` in TEAM.json already serves this role.
- **Dynamic worker memory**: `spawn_agent` workers are task-scoped and ephemeral.
- **UI for memory**: the sidecar's ETS/Typesense memory is opaque to the CLI UI.
- **`write_skill` global scope**: agent-written skills are workspace-only. Users
  can manually place skills in `~/.planck/skills/` for global availability.
- **Layer 2 reflection**: periodic mid-session reflection is out of scope.
- **Vector search**: `session_search` uses FTS only (Typesense in sidecar,
  SQLite in core when implemented). Embedding-based recall is a future concern.
